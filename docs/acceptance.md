# 阶段 1 验收

范围只有两条主路线，外加左栏底部的设置：看板 `/`、任务页 `/task/:id`、设置 `/settings`。没有对话、自动化、扩展、模板编辑器、费用统计、并发设置。

对照样稿：`docs/design/ui-board4.html`、`docs/design/ui-min3.html`。颜色只用黑白灰（`@theme`），不抄样稿里的琥珀、绿、蓝。

怎么读「在哪验」：

- **替身**：这台机器上 `pnpm test` 和 `MUFU_AGENT=fake pnpm start` 就能看。
- **Mac**：要在你的电脑上跑 `pnpm verify:mac`，或双击 `mufu.app`。Linux 上打不出、也跑不了这个包。

## 协调 Agent（lead agent stubbed in phase 1）

阶段 1 的协调 Agent 是桩：不调用 OpenRouter，也不读钥匙串里的 key。守护进程在任务开始时写下面这一条固定消息。模板里每一个已经完成的阶段，它再钉一条重点。正文和理由都是 `阶段完成：阶段名 — 被钉消息开头约 30 字`，事件里的作者是 `lead`，界面写成「协调 Agent」。它不写卡片摘要，也不再发第二句聊天。样稿 `ui-min3.html` 里协调 Agent 的其它句子不要拿来判失败。Codex、Claude 不能钉重点，人也不能在界面上手动钉。

**任务页里的那一条。** 作者显示「协调 Agent」。正文用模板标题和阶段名拼出来，阶段之间是顿号：

- 修 bug：`用「修 bug」流程处理：复现、修复、PR 与 CI、验收。`
- 新功能：`用「新功能」流程处理：方案、实现、PR 与 CI、验收。`

样稿的「用「修 bug」流程处理：复现、修复、提 PR，最后给你验收。」不是这句。样稿的「可以验收了。有 2 条重点建议你先看一下。」也不是桩写的。手写夹具把后一句放在最终门禁被批准之后才回放，作者名字相同，但是一条普通代理消息。批准之后任务会去合并，成功就离开看板。

**看板卡片标题下面的一行。** 待验收时这一行来自事件，形如 `PR #50 · CI 通过 · 无冲突 · +38 −12`，不把 CI 状态再单独拆成一个「通过」。其它列：有失败时按失败类别写人话（冲突、CI、环境各一句，不出现命令原文）；否则是最后一条不是「你」发的消息。进行中的卡片另外显示这一轮已经跑了多久。

**重点、未读条、左栏加粗。** 重点只来自协调 Agent 写进日志的 `pin.added`，作者必须是 `lead`。别的作者会被折叠丢掉，界面不检查作者。桩按任务快照里的阶段钉，不按模板名写分支，每个阶段最多 5 条，同一阶段只钉一次。手写修 bug 夹具停在待验收、最终门禁还没批时，复现、修复、PR 与 CI 已经完成，验收还没有，所以未读条是三条。正文带阶段名和被钉消息的开头，右边界面写 `协调 Agent ›`：

- 复现钉在 Claude 的「已复现。接口返回空列表时 data 是 undefined，补了一个失败的测试。」上。左侧灰线，名字旁边是 `📌 阶段完成：复现 — …`。
- 修复钉在 Codex 的「已修复，加了空值兜底和 2 个测试，提交了 PR #50。」上。左侧灰线，名字旁边是 `📌 阶段完成：修复 — …`。
- PR 与 CI 钉在系统消息「CI 第一次失败，已修复后通过」上，这句后面是 `📌 阶段完成：PR 与 CI — …`。

未读条的标题是 `📌 3 条重点未读`，按钮文字是 `全部已读`。每一行是 `阶段完成：阶段名 — 被钉消息开头约 30 字`，右边写 `协调 Agent ›`，不写 `lead`。点一行，滚到被钉的那条消息。点「全部已读」之后条消失，左栏不再为这三条加粗。左栏的黑点仍是待处理门禁，`!` 仍是失败。批准最终门禁之后，桩再给验收阶段钉同一句格式的重点，然后去合并；成功就离开看板。打回不给验收阶段钉这一条，阶段回到模板的 `reject_to`（修 bug 是修复，新功能是实现）。

## 架构（对照代码，不是点界面）

- `packages/core` 不引用 Electron、SQLite、gh 的实现、适配器。GitHub 只是接口。`DEV_PORT` 和 `DAEMON_WS_PORT` 在 `@mufu/schema`，守护进程和看板都从那里读，不在 core。
- dependency-cruiser 禁止包环，并卡着 core / adapters / daemon / cli / app 的方向，以及界面里 modules、common、api 的方向。
- 适配器对外只有 `startSession`。订阅检查、去掉环境里的 key、找二进制、恢复和中断都在实现里。
- 事件日志只追加，只有守护进程在写。事件带 `schemaVersion`。界面状态从事件折出来。
- `docs/glossary.md` 里的词和代码标识符一致。
- 界面目录是 modules / common / api / store。只有 `api/client` 连守护进程。服务端数据用 TanStack Query，加载、空、错都有。
